# Design

How products look and behave, written precisely enough that a design can be
generated from it: numbers instead of adjectives, tokens as data, components
and screens as specifications.

| Folder | What it holds |
|---|---|
| [`foundations/`](./foundations/README.md) | Principles that hold for any product — hierarchy, type, colour, spacing, motion, accessibility. |
| [`languages/`](./languages/README.md) | A design language per kind of product: how it looks and behaves. |
| [`system/`](./system/README.md) | The design system — tokens and components. |
| [`patterns/`](./patterns/README.md) | Screen recipes — a list, a detail, settings, an empty state. |
| [`references/`](./references/README.md) | Examples, good and bad, and what each one teaches. |
| [`skills/`](./skills/README.md) | Agent skills built from the folders above. |

How a front end builds this in code is in
[`software/principles/web/ui/`](../software/principles/web/ui/README.md).
